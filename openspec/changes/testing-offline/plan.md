# Plan Tecnico: Offline Tests for SalesViewModelV2 and InventoryDeductions

Spec ID: `testing-offline`

## Lectura Inicial Obligatoria

- `AGENTS.md`
- `openspec/constitution.md`
- `SalesViewModelV2.kt`, `InventoryDeductions.kt`, `CartManager.kt`, `CheckoutUseCase.kt`

## Punto de Entrada Real

- ViewModel: `SalesViewModelV2` is the central hub for the sales UI.
- Repositorio/data: `InventoryDeductions` calculates ingredient deductions used during offline fallback persistence in `CheckoutUseCase`.
- Tests: `app/src/test/` for Unit tests and `app/src/androidTest/` for instrumented integration tests.

## Archivos Probables

- `app/src/test/java/com/bocatta/pos/data/repository/InventoryDeductionsTest.kt`
- `app/src/test/java/com/bocatta/pos/presentation/viewmodel/SalesViewModelV2Test.kt`
- `app/src/androidTest/java/com/bocatta/pos/OfflineCheckoutInstrumentedTest.kt`

## Estrategia

1. **Unit Testing `InventoryDeductions`**: Add tests to `InventoryDeductionsTest.kt` to explicitly cover `resolverDescuentoOpcion` interacting with `configSchema` from `SalesInventoryProductV2`.
2. **Unit Testing `SalesViewModelV2`**: Create `SalesViewModelV2Test.kt`. Use `mockk` for its many dependencies. Test setting `isOnline = false` and ensure that offline methods gracefully handle state changes. Test cart management state (e.g. adding items off-network).
3. **Instrumented Testing `OfflineCheckoutInstrumentedTest`**: Set up a real (in-memory) `OfflineDatabase`. Initialize `SalesViewModelV2` and call `agregarAlCarrito` -> `checkoutUseCase` (or equivalent) while offline. Verify that `OfflineDatabase` contains the correctly mapped records with deductions generated by `InventoryDeductions`.
